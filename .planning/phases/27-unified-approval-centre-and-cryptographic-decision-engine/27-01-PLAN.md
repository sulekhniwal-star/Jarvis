# Plan 27.1: Cryptographic Token Engine, Repository Enhancements & Decision API

## Objective
Implement HMAC-SHA256 cryptographic approval tokens, enhance `ApprovalRepository` with multi-status query filtering and aggregate metric computation, and build dedicated REST API endpoints for listing approvals, viewing details, and recording verified decisions.

## Task Breakdown

### Task 1: Cryptographic Approval Token Engine
- Create `src/lib/approvals/approval-token.ts`:
  - `generateApprovalToken(payload, secret?)`: Generates HMAC-SHA256 signature using canonical string `id:action_type:target_resource:user_id:expires_at`.
  - `verifyApprovalToken(token, expected, secret?)`: Validates token integrity using timing-safe comparison (`crypto.timingSafeEqual`).
  - Fallback secret lookup: `process.env.APPROVAL_SECRET` -> `process.env.SUPABASE_SERVICE_ROLE_KEY` -> internal fallback.

### Task 2: ApprovalRepository Enhancements
- Modify `src/lib/repositories/approval-repository.ts`:
  - Add `listApprovals(userId, filters)`:
    - Filters: `status` (`all`, `pending`, `approved`, `rejected`, `expired`), `actionType`, `search`, `limit`, `offset`.
    - Auto-detects and updates expired approvals when queried.
  - Add `getApprovalMetrics(userId)`:
    - Returns `{ total, pending, approved, rejected, expired }`.

### Task 3: REST API Endpoints
- Create `src/app/api/approvals/route.ts`:
  - `GET`: Authenticated endpoint returning filtered approvals and metrics summary.
  - `POST`: Validates creation payload via Zod (`actionType`, `targetResource`, `scope`, `expiresAt`, optional `taskId`). Automatically generates cryptographic token and attaches to response.
- Create `src/app/api/approvals/[id]/route.ts`:
  - `GET`: Fetches single approval by ID with linked task and project metadata.
- Create `src/app/api/approvals/[id]/decision/route.ts`:
  - `POST`: Accepts `{ decision: 'approved' | 'rejected', reason?: string, token?: string }`.
  - Enforces `verifyApprovalToken()` if token is provided or action is high-risk.
  - Validates approval state machine (`pending` -> `decision`) and non-expiration.
  - Records decision, updates `decided_at`, and returns updated record.

### Task 4: Unit & Integration Tests
- Create `tests/unit/approvals/approval-token.test.ts`:
  - Validates token generation, valid verification, altered target/action rejection, timing-safe equality.
- Update `tests/unit/repositories/approval-repository.test.ts`:
  - Tests `listApprovals` with all filters and `getApprovalMetrics`.
- Create `tests/unit/api/approvals-routes.test.ts`:
  - Tests GET /api/approvals, POST /api/approvals, and POST /api/approvals/[id]/decision (valid token, invalid token, expired approval).

# Plan 13.1: Pre-Push Validation Engine & Domain Models

## Objective
Implement a robust, automated pre-push validation engine (`src/lib/git/push-validator.ts`) that programmatically verifies repository invariants before requesting or executing any remote push: strictly locked to `main`, clean working tree (no uncommitted or untracked changes), verified ahead commit count > 0, and 0 secrets detected in outgoing commit diffs (`REQ-GH-03`, `NFR-SEC-01`).

  <action>
    1. Update `src/lib/git/types.ts`:
       - Add `PrePushCommitSummary`: `{ sha: string; shortSha: string; message: string; author: string; date: string }`
       - Add `PrePushValidationResult`:
         ```typescript
         export interface PrePushValidationResult {
           isReady: boolean;
           activeBranch: string;
           isClean: boolean;
           aheadCount: number;
           behindCount: number;
           remoteRef: string;
           headCommitSha: string;
           headCommitMessage: string;
           commits: PrePushCommitSummary[];
           filesChanged: string[];
           hasSecrets: boolean;
           detectedSecretPatterns: string[];
           errors: string[];
         }
         ```
       - Add `PrePushValidationOptions`: `{ cwd?: string; remoteRef?: string; skipSecretScan?: boolean }`
    2. Author `src/lib/git/push-validator.ts`:
       - Implement `validatePrePush(options?: PrePushValidationOptions): Promise<PrePushValidationResult>` (or synchronous / async wrapper):
         - Check active branch using `verifyActiveBranchIsMain(cwd)`: must be `"main"`. If not, add error `"Active branch is '<branch>', but only 'main' is permitted."`
         - Check working tree cleanliness using `getWorkingTreeStatus(cwd)`: must have `isClean: true`. If dirty, list modified and untracked files in errors.
         - Check remote ref (default `"origin/main"`):
           - Query ahead count: `git rev-list --count <remoteRef>..HEAD` (or `origin/main..main`).
           - If ahead count === 0, record error `"No local commits ahead of remote to push."`
           - Query behind count: `git rev-list --count HEAD..<remoteRef>`.
           - If behind count > 0, record error `"Local branch is behind remote by <count> commits. Pull or sync required."`
         - Query commits to push: `git log <remoteRef>..HEAD --format=%H%x09%h%x09%s%x09%an%x09%aI`
         - Query files changed: `git diff --name-only <remoteRef>..HEAD`
         - Query secrets: run diff scanner on `<remoteRef>..HEAD` diff using the secret patterns in `diff.ts`.
         - Compute `isReady = errors.length === 0 && !hasSecrets && aheadCount > 0 && isClean && activeBranch === "main"`.
    3. Export validator from `src/lib/git/index.ts`.
  </action>
</task>

      4. Zero commits ahead (ahead count = 0) -> `isReady: false`, reports no commits to push.
      5. Local branch behind remote (behind count > 0) -> `isReady: false`, reports behind remote.
      6. Secret detected in commit diff (e.g. `ghp_...` or private key) -> `isReady: false`, `hasSecrets: true`.
      7. Git execution error (e.g. invalid repo or missing remote) -> graceful error handling, returns `isReady: false` with error message.

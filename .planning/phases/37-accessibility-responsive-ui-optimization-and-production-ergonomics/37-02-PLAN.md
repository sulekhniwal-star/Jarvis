# Plan 37.2: Cross-Device Responsive Layouts, Contrast Verification & Accessibility Audit Report

## Objective
Implement an automated color contrast and touch target auditor, verify responsive layout behavior across mobile (375px) to desktop (1440px) viewports, and generate `docs/ACCESSIBILITY-AUDIT.md` certifying WCAG 2.1 AA compliance (`REQ-UI-01`, `NFR-A11Y-01`).

## Task Breakdown

### Task 1: Color Contrast & Accessibility Auditor Service
- Create `src/lib/ui/accessibility-auditor.ts`:
  - Implement `AccessibilityAuditor`:
    - `calculateLuminance(hex: string): number`: Computes sRGB relative luminance according to WCAG 2.1 formula.
    - `calculateContrastRatio(fgHex: string, bgHex: string): number`: Calculates contrast ratio $(L_1 + 0.05) / (L_2 + 0.05)$.
    - `auditThemeContrast()`: Evaluates primary text, muted text, status text, and accent cyan across background surfaces (`#07111F`, `#0B172B`, `#111E33`).
    - `auditTouchTargets(targets: TouchTargetSpec[])`: Verifies all interactive buttons and mobile elements meet $44 \times 44$px minimum dimensions.
    - `generateComplianceReport()`: Outputs complete WCAG 2.1 AA compliance report.

### Task 2: Responsive & Accessibility Integration Test Suite
- Create `tests/integration/responsive-accessibility.test.tsx`:
  - Test mathematical accuracy of contrast ratio calculations.
  - Assert that all primary and secondary text tokens meet the 4.5:1 contrast requirement against dark surfaces.
  - Assert that accent colors and graphical elements meet the 3:1 contrast requirement.
  - Assert that mobile drawer, touch targets, and action buttons meet $44 \times 44$px touch sizing.
  - Assert that all 10 core views utilize responsive grid/flex layouts without fixed overflowing widths.

### Task 3: Master Accessibility Audit Documentation
- Create `docs/ACCESSIBILITY-AUDIT.md`:
  - Document WCAG 2.1 AA compliance across all 4 principles:
    - *Principle 1 (Perceivable):* Text alternatives, contrast ratios, text resizing, sensory characteristics.
    - *Principle 2 (Operable):* Keyboard navigation, no keyboard traps, skip link, visible focus, touch targets $\ge 44 \times 44$px.
    - *Principle 3 (Understandable):* Language attributes (`<html lang="en">`), clear error messaging, predictable navigation.
    - *Principle 4 (Robust):* ARIA compatibility, valid semantic HTML5 landmarks, screen reader accessibility.
  - Include contrast verification tables with exact ratios.

### Task 4: Full Repository Regression & Production Build Gate
- Run `cmd /c npx vitest run tests/integration/responsive-accessibility.test.tsx`.
- Run complete Vitest suite across all test files (`cmd /c npx vitest run`).
- Run Next.js production build (`cmd /c npm run build` with `BypassSandbox: true`).
- Verify zero TypeScript errors and zero warnings.

# Plan 17.1: GitHub Client Workflow Dispatcher & GitHub Actions Sandbox Runner

## Objective
Extend `GitHubClient` with workflow dispatch capabilities and implement `GitHubActionsSandboxRunner` to execute coding agent tasks inside ephemeral GitHub Actions container runners with zero master secret leakage and strict `main`-branch locking (`REQ-EX-03`, `NFR-SEC-01`, `NFR-SEC-02`).

<task type="auto">
  <name>Implement GitHubActionsSandboxRunner</name>
  <files>
    src/lib/agents/engine/sandbox/github-actions-runner.ts
  </files>
  <action>
    Create `src/lib/agents/engine/sandbox/github-actions-runner.ts`:
    1. Class `GitHubActionsSandboxRunner implements ISandboxRunner`:
       - `readonly mode = "github_actions"`
       - Constructor accepts `GitHubClient` and `SandboxExecutionConfig`.
       - `validateEnvironment(): Promise<EngineValidationResult>`:
         - Checks if `GITHUB_TOKEN` is available and repository is accessible via `gitHubClient.getRepository()`.
       - `execute(context: CodingTaskContext): Promise<CodingTaskResult>`:
         - Verifies `context.targetBranch === "main"` (`NFR-SEC-01`).
         - Formulates safe workflow dispatch inputs:
           - `taskId`: `context.taskId`
           - `runId`: `context.runId`
           - `stepId`: `context.stepId || ""`
           - `allowedFiles`: `JSON.stringify(context.allowedFilePatterns)`
           - `scopedInstructions`: `context.scopedInstructions`
         - Sanitizes inputs to ensure no master credentials are passed (`NFR-SEC-02`).
         - Calls `gitHubClient.dispatchWorkflow(owner, repo, workflowFileName, "main", inputs)`.
         - Polls for workflow run using `listWorkflowRuns` or status checks until conclusion (`"success" | "failure" | "cancelled" | "timed_out"`).
         - Returns structured `CodingTaskResult`.
  </action>
  <verify>
    Run `pnpm.cmd exec tsc --noEmit` to verify implementation.
  </verify>
  <done>
    GitHubActionsSandboxRunner dispatches workflows and maps run conclusion to CodingTaskResult.
  </done>
</task>

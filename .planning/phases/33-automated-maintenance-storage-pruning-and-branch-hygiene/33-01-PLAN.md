# Plan 33.1: Automated Storage Pruning & Retention Engine

## Objective
Implement `StoragePruningService` in `src/lib/ops/storage-pruner.ts`, providing automated retention pruning for ephemeral artifacts older than 30 days, automated expiration of stale pending approvals with audit ledger tracking, and ephemeral log cleaning (`REQ-OPS-03`), accessible via REST API and CLI runner.

## Task Breakdown

### Task 1: Storage Pruning Service & Domain Types
- Create `src/lib/ops/storage-pruner.ts`:
  - Define `PruningOptions`:
    - `retentionDays?: number` (default: 30)
    - `dryRun?: boolean` (default: false)
    - `tempDirPaths?: string[]`
  - Define `MaintenanceExecutionReport`:
    - `success: boolean`
    - `timestamp: string`
    - `durationMs: number`
    - `isDryRun: boolean`
    - `artifactsPruned: number`
    - `bytesReclaimed: number`
    - `approvalsExpired: number`
    - `tempFilesCleaned: number`
    - `errors: string[]`
  - Implement `StoragePruningService`:
    - `pruneOldArtifacts(options)`: queries `run_artifacts` older than cutoff, deletes disk storage files, removes database records, and accumulates reclaimed bytes.
    - `expireStaleApprovals(options)`: queries `approvals` where `status === "pending"` and `expires_at < new Date()`, sets `status = "expired"`, and writes hash-chained audit events via `AuditLedgerService`.
    - `pruneTemporaryLogs(options)`: cleans transient log and scratch files.
    - `runFullMaintenance(options)`: executes complete maintenance lifecycle with error isolation and aggregated reporting.

### Task 2: REST API & CLI Runner
- Create `src/app/api/maintenance/prune/route.ts`:
  - `POST`: Authenticated endpoint running maintenance pruning. Accepts `{ retentionDays?: number, dryRun?: boolean }`.
  - `GET`: Authenticated endpoint returning latest maintenance status and storage metrics.
- Create `scripts/maintenance-runner.ts`:
  - CLI script supporting `--retention-days <N>`, `--dry-run`, and `--json`.
  - Update `package.json`: Add `"maintenance:prune": "tsx scripts/maintenance-runner.ts"`.

### Task 3: Unit & API Route Tests
- Create `tests/unit/ops/storage-pruner.test.ts`:
  - Test pruning artifacts older than 30 days while preserving recent artifacts.
  - Test stale approval expiration and audit ledger event generation.
  - Test dry-run mode reporting targets without performing destructive mutations.
  - Test error handling when disk files or database records are inaccessible.
- Create `tests/unit/api/maintenance-routes.test.ts`:
  - Test `POST /api/maintenance/prune` authentication and execution.
  - Test `GET /api/maintenance/prune` returning status and storage estimates.

# Plan 29.1: Process Cancellation Registry, Process Tree Dispatcher & Kill Switch Engine

## Objective
Implement the cross-platform `ProcessCancellationRegistry` that tracks active agent subprocesses and provides process-tree termination, the `EmergencyKillSwitchService` that halts active processes, cancels runs and tasks, revokes pending approvals, and writes an audit log in `< 1000ms`, and expose REST API endpoints.

## Task Breakdown

### Task 1: Process Cancellation Registry & Tree Dispatcher (`REQ-SEC-02`)
- Create `src/lib/system/process-registry.ts`:
  - Singleton `ProcessCancellationRegistry`.
  - Methods:
    - `register(runId: string, process: ChildProcessLike, metadata?: Record<string, unknown>): string`
    - `unregister(registrationId: string): void`
    - `getActiveProcesses(): RegisteredProcess[]`
    - `terminateAll(signal?: "SIGTERM" | "SIGKILL"): Promise<TerminationSummary>`
      - Dispatches cross-platform tree kill: on Windows executes `taskkill /pid <PID> /T /F`; on POSIX dispatches `SIGTERM` followed by `SIGKILL`.
      - Measures execution duration.
- Modify `src/lib/agents/engine/aider/aider-adapter.ts`:
  - Register spawned child processes in `ProcessCancellationRegistry` on launch and unregister on close.

### Task 2: Emergency Kill Switch Service (`REQ-SEC-01`, `NFR-PERF-03`)
- Create `src/lib/system/kill-switch.ts`:
  - `EmergencyKillSwitchService`:
    - Method `executeEmergencyStop(userId: string, source: "web" | "telegram" = "web"): Promise<KillSwitchResult>`
      1. Starts high-resolution stopwatch (`performance.now()`).
      2. Invokes `processRegistry.terminateAll("SIGKILL")`.
      3. Database state updates:
         - Cancels active `agent_runs` (`status IN ('queued', 'running', 'verifying')` -> `failed` with error summary).
         - Cancels active `tasks` (`status IN ('running', 'verifying', 'planned', 'awaiting_approval')` -> `cancelled`).
         - Revokes pending `approvals` (`status = 'pending'` -> `rejected` with `decision_reason: 'Revoked by Emergency Kill Switch'`).
      4. Logs immutable record in `audit_events` with details.
      5. Calculates total duration and verifies `< 1000ms` sub-second performance.
    - Method `getKillSwitchStatus(userId: string): Promise<KillSwitchStatus>`

### Task 3: REST API Endpoints
- Create `src/app/api/system/kill/route.ts`:
  - `POST`: Invokes `executeEmergencyStop(userId, source)`. Returns 200 with result.
- Create `src/app/api/system/kill/status/route.ts`:
  - `GET`: Returns active processes count, last kill switch event, and system readiness.

### Task 4: Unit & Integration Tests
- Create `tests/unit/system/process-registry.test.ts`: Test process registration, unregistration, and tree kill dispatching.
- Create `tests/unit/system/kill-switch.test.ts`: Test end-to-end execution, database cancellations, audit event logging, and sub-second execution duration.
- Create `tests/unit/api/kill-switch-routes.test.ts`: Test `POST /api/system/kill` and `GET /api/system/kill/status`.

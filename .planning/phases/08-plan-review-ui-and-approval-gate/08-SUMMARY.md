# Phase 8 Summary: Plan Review UI & Approval Gate

## 1. Execution Overview

Phase 8 delivered the human-in-the-loop Plan Review UI and Approval Gate for Milestone 2 (Specification & Planning Workflow). This safety-critical capability exposes execution plans generated by the Planner Agent in an interactive visual DAG viewer organized by wave, displays automated risk assessments, flags human approval requirements, and provides double-submission protected decision controls to approve plans or request revisions.

- **Phase Objective:** Author visual plan review interface and backend decision lifecycle allowing humans to inspect plans, evaluate risks, review wave ordering, approve plans into execution, or request Socratic revisions (`REQ-PLAN-04`).
- **Requirements Satisfied:**
  - `REQ-PLAN-04`: Visual Plan Review & Human Approval Gate (review screen, DAG viewer, risk breakdown, and approval/revision decision endpoints).
  - `REQ-REPO-03`: Persistent approval records and state tracking via `ApprovalRepository` and `PlanRepository`.
  - `NFR-REL-01` & `NFR-REL-02`: Deterministic state transitions via `TaskStateMachine` and strict schema validation.
- **Git Compliance:** 100% compliant with `main`-only policy across local commits `9233bae` (Wave 1 UI) and `5a01ef9` (Wave 2 Decision API & State Machine).

## 2. Key Deliverables & Artifacts

### 2.1 Wave 1 (Plan 8.1) — Visual Plan Review Interface & DAG Components
- **Header & Metric Counters (`src/components/plan-review/plan-review-header.tsx`):**
  - Displays task title, project breadcrumb, plan version badge, task status pill, and statistics (total steps, total waves, targeted files).
- **Plan Risk Banner (`src/components/plan-review/plan-risk-banner.tsx`):**
  - Displays overall risk level badge (`low`, `medium`, `high`, `critical`), detected risk factors (e.g. database migrations, remote git actions), required human approval tags, and mitigation recommendations.
- **Plan DAG Viewer (`src/components/plan-review/plan-dag-viewer.tsx`):**
  - Renders execution steps partitioned into sequential wave groups.
  - Step cards highlight action types (`create`, `modify`, `delete`, `command`, `migration`), prerequisites/dependencies, expandable file target lists, verification commands, and rollback procedures.
- **Plan Decision Controls (`src/components/plan-review/plan-decision-controls.tsx`):**
  - "Approve Plan" primary action with double-submission prevention and loading spinner.
  - "Request Revision" secondary action toggling feedback input textarea for operator guidance.
- **Client Coordinator & Page (`src/components/plan-review/plan-review-view.tsx`, `src/app/tasks/[id]/plan/page.tsx`):**
  - Client component handling asynchronous decision posting to `/api/tasks/[id]/plan/decision`.
  - Next.js App Router server page fetching task, latest plan, and specification, rendered inside `AppShell`.
- **Component Unit Test Suite (`tests/unit/components/plan-review.test.tsx`):**
  - 5/5 tests passing: validates header rendering, risk banner elements, wave grouping, step card expansion, approve callback, and revision feedback submission.

### 2.2 Wave 2 (Plan 8.2) — Plan Decision API, State Machine Revisions & Approval Lifecycle
- **Task State Machine Revision Transitions (`src/lib/state-machines/task-state-machine.ts`):**
  - Added transitions: `planned -> specifying` and `awaiting_approval -> specifying` to support revision requests when plans require adjustment.
- **Plan Decision Route Handler (`src/app/api/tasks/[id]/plan/decision/route.ts`):**
  - `POST /api/tasks/[id]/plan/decision` route handler accepting `{ decision, feedback, userId }`.
  - If `decision === 'approve'`:
    - Updates plan status to `approved`.
    - If plan required approvals, records approval via `ApprovalRepository.create(...)`.
    - Transitions task status to `running` via `TaskStateMachine.assertTransition`.
  - If `decision === 'request_revision'`:
    - Updates plan status to `superseded`.
    - Transitions task status to `specifying` via `TaskStateMachine.assertTransition`.
- **Decision & State Machine Test Suites:**
  - `tests/unit/state-machines/task-state-machine.test.ts` (5/5 tests passing).
  - `tests/unit/api/tasks-plan-decision-route.test.ts` (5/5 tests passing).

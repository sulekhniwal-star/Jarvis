# Plan 30.2: Automated Database Backup Runner & Disaster Recovery Drill Test Suite

## Objective
Implement an automated database snapshot runner with compression, AES-256-GCM authenticated encryption, SHA-256 integrity checksum verification, retention rotation, and an end-to-end disaster recovery drill test suite verifying zero-loss restoration under `REQ-OPS-01`.

## Task Breakdown

### Task 1: Automated Backup Snapshot Runner (`src/lib/ops/backup-runner.ts`)
- Implement `BackupSnapshotRunner`:
  - `createSnapshot(options?: BackupOptions): Promise<BackupResult>`:
    - Extracts records across critical tables (`projects`, `tasks`, `agent_runs`, `approvals`, `cost_records`, `memories`, `audit_events`).
    - Constructs canonical JSON payload with schema metadata, timestamp, table counts, and dataset records.
    - Compresses snapshot data using `zlib.gzipSync`.
    - Encrypts payload with `AES-256-GCM` using 256-bit key, 96-bit random IV, and 128-bit authentication tag.
    - Saves encrypted snapshot file to target destination (e.g. `backups/backup-<timestamp>.enc.gz`).
    - Computes SHA-256 digest of the output file and writes `.sha256` verification checksum file alongside.
    - Returns `{ snapshotId, filename, checksum, recordCount, sizeBytes, durationMs, timestamp }`.
  - `verifySnapshotChecksum(snapshotPath: string): Promise<boolean>`:
    - Reads `.sha256` file, recomputes SHA-256 digest of snapshot file, and asserts match.
  - `decryptSnapshot(snapshotPath: string, key?: string): Promise<BackupDataset>`:
    - Reads encrypted file, splits IV, ciphertext, and auth tag.
    - Decrypts with AES-256-GCM and verifies authentication tag integrity.
    - Decompresses gzip and parses JSON dataset.
  - `rotateSnapshots(backupDir: string, maxRetention: number = 7): Promise<{ retained: string[], pruned: string[] }>`:
    - Lists snapshot files in backup directory, sorts descending by timestamp, keeps the newest $N$ snapshots, and removes older snapshot and checksum files.

### Task 2: Disaster Recovery Drill Harness (`src/lib/ops/recovery-drill.ts`)
- Implement `DisasterRecoveryDrill`:
  - `executeDrill(options?: DrillOptions): Promise<RecoveryDrillResult>`:
    - Stage 1: Captures baseline pre-backup database state (row counts, record hashes across all tables).
    - Stage 2: Executes `BackupSnapshotRunner.createSnapshot()`.
    - Stage 3: Verifies SHA-256 checksum integrity of the generated snapshot.
    - Stage 4: Simulates a disaster scenario (e.g. table truncation or corrupted state in target test schema/database).
    - Stage 5: Decrypts, verifies auth tag, and restores snapshot records in strict topological foreign-key order.
    - Stage 6: Compares post-restoration database state with pre-backup baseline.
      - Asserts 100% row count match for every table.
      - Asserts 100% record hash equality for all fields.
      - Asserts foreign key consistency.
    - Stage 7: Evaluates Recovery Time Objective (RTO) against target (< 1 hour; drill execution benchmark < 15 seconds) and Recovery Point Objective (RPO < 24 hours).
    - Returns detailed `RecoveryDrillResult` including table-by-table parity metrics, duration, RTO/RPO compliance status, and integrity confirmation.

### Task 3: CLI Entrypoint Scripts & Package Configuration
- Create `scripts/backup-runner.ts`:
  - Standalone script to execute a manual or cron-driven backup snapshot and print summary.
- Create `scripts/recovery-drill.ts`:
  - Standalone script to execute the disaster recovery drill, print a human-readable recovery report, and exit 0 (pass) or 1 (fail).
- Update `package.json`:
  - Add `"backup:snapshot": "tsx scripts/backup-runner.ts"`.
  - Add `"backup:drill": "tsx scripts/recovery-drill.ts"`.
- Create `docs/AUDIT_AND_BACKUP_GUIDE.md`:
  - Comprehensive reference guide covering:
    - Cryptographic hash-chaining structure in `audit_events`.
    - Backup encryption specifications (AES-256-GCM, IV length, auth tag).
    - Retention schedule and rotation procedures.
    - Step-by-step manual disaster recovery protocol following `docs/BACKUP_AND_RECOVERY.md`.

### Task 4: Unit & Integration Tests
- `tests/unit/ops/backup-runner.test.ts`:
  - Test snapshot creation, gzip compression, and encrypted output structure.
  - Test SHA-256 checksum calculation and verification.
  - Test AES-256-GCM decryption roundtrip and auth tag tampering detection.
  - Test retention rotation logic (pruning oldest beyond threshold).
- `tests/unit/ops/recovery-drill.test.ts`:
  - Test full end-to-end recovery drill pipeline with simulated disaster.
  - Test zero-loss restoration verification (100% table and row parity).
  - Test detection of data loss / missing rows during restoration comparison.
  - Test RTO and RPO benchmark evaluations.

# Plan 36.1: Cryptographic Timing-Safety, Boundary Hardening & Security Audit Suite

## Objective
Harden cryptographic verifications with constant-time equality comparisons, eliminate sandbox directory traversal risks, and implement `SecurityAuditSuite` for automated security control verification (`REQ-SEC-03`, `NFR-SEC-05`).

## Task Breakdown

### Task 1: Timing-Safe Telegram Webhook Secret Verification
- Modify `src/lib/telegram/guard.ts`:
  - Update `verifyWebhookSecret(headerSecret: string | null | undefined)`:
    - If `process.env.TELEGRAM_WEBHOOK_SECRET` is not set, return true.
    - If `headerSecret` is missing, return false.
    - Use `crypto.createHash('sha256')` to normalize both header secret and expected secret into uniform 32-byte buffers.
    - Compare using `crypto.timingSafeEqual(headerBuf, expectedBuf)` to guarantee constant-time verification regardless of input length.

### Task 2: Sandbox Directory Traversal & Root Escape Defenses
- Modify `src/lib/agents/engine/verification/diff-inspector/boundary-validator.ts`:
  - Enhance `validateFileBoundaries`:
    - Check for directory traversal indicators: `..` path segments, `/` or `\` leading slashes, drive letters (e.g. `C:`), or null bytes (`\0`).
    - Emit violation with code `PATH_TRAVERSAL_DETECTED` and severity `blocker`.
    - Ensure traversal check runs before pattern matching to prevent bypass.

### Task 3: Security Audit Suite Engine
- Create `src/lib/security/audit-suite.ts`:
  - Implement `SecurityAuditSuite`:
    - `auditCryptographicPrimitives()`: Verifies that approval tokens, GitHub webhooks, and Telegram secrets all use constant-time equality comparisons.
    - `auditPathBoundaryEnforcement()`: Evaluates directory traversal detection against malicious paths (`../../etc/passwd`, `C:\Windows\System32`, `..\config\.env`).
    - `auditSecretScannerCoverage()`: Tests secret scanner against baseline known credential patterns (OpenAI, Stripe, GitHub, AWS, DB URIs).
    - `auditCircuitBreakerFailsafes()`: Validates that missing cost repositories fail-closed.
    - `runFullSecurityAudit()`: Runs all checks and returns structured `SecurityAuditReport`.

### Task 4: Unit Test Suite
- Create `tests/unit/security/crypto-and-boundaries.test.ts`:
  - Test timing-safe webhook verification with matching, mismatched, and empty secrets.
  - Test directory traversal detection on diverse attack strings (`../../secret`, `..\\windows`, `/etc/shadow`, `C:/secrets.env`).
  - Test `SecurityAuditSuite` running complete suite and returning passed status.

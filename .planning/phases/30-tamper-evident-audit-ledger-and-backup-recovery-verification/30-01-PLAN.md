# Plan 30.1: Tamper-Evident Audit Ledger Core, Hash Chaining & Activity Viewer

## Objective
Establish the append-only cryptographic hash-chained audit ledger service, REST API endpoints, on-demand chain integrity verification, and the `/audit` management portal interface satisfying `REQ-AUD-01`.

## Task Breakdown

### Task 1: Cryptographic Hash Chaining Service (`src/lib/audit/audit-ledger.ts`)
- Implement `AuditLedgerService`:
  - `computeBlockHash(params: HashParams): string`:
    - Deterministically serializes input fields (sequence, prev_hash, event_type, resource_type, resource_id, canonical JSON payload, timestamp).
    - Computes SHA-256 hash via Node.js `crypto`.
  - `recordEvent(input: AuditEventInput): Promise<AuditEventRecord>`:
    - Queries the latest audit event for the user/system to obtain current head hash and sequence.
    - If no events exist, sets `prev_hash` to genesis constant (`"0".repeat(64)`) and `sequence = 1`.
    - Generates new SHA-256 block hash.
    - Inserts event into `audit_events` with `_audit: { sequence, prev_hash, hash }` embedded in `details`.
  - `verifyChainIntegrity(options?: { userId?: string, limit?: number }): Promise<AuditChainVerificationResult>`:
    - Scans audit events in chronological order.
    - Verifies genesis hash linkage on initial block.
    - Verifies $H_k = \text{SHA256}(...)$ and $\text{prev\_hash}_k = H_{k-1}$ for each block.
    - Asserts sequence continuity ($seq_k = seq_{k-1} + 1$).
    - Returns `{ isValid: boolean, verifiedCount: number, headHash: string, corruptedEventId?: string, error?: string }`.
  - `listEvents(userId: string, filters: AuditFilters): Promise<{ events: AuditEventRecord[], total: number }>`:
    - Returns paginated and filtered audit events with type and resource filtering.

### Task 2: Audit Ledger REST API Routes
- Create `src/app/api/audit/route.ts`:
  - `GET`: Authenticated endpoint returning paginated audit records with filtering options (`event_type`, `resource_type`, `page`, `limit`).
  - `POST`: Authenticated endpoint to append an audit event into the ledger via `AuditLedgerService`.
- Create `src/app/api/audit/verify/route.ts`:
  - `GET`: Authenticated endpoint executing `AuditLedgerService.verifyChainIntegrity()` and returning integrity status, verified block count, and head hash.

### Task 3: Audit Ledger Web UI Components & Route
- Create `src/components/audit/audit-chain-badge.tsx`:
  - Displays cryptographic chain integrity status:
    - Emerald badge when `isValid` with count of verified blocks.
    - Rose badge when `isValid === false` indicating chain tampering with error reason.
    - Loading state when verifying.
- Create `src/components/audit/audit-ledger-table.tsx`:
  - Table displaying timestamp, event type, resource details, actor, truncated `prev_hash` and `hash` badges, and expandable JSON inspector drawer.
  - Filter bar with search, event type dropdown, and date controls.
- Create `src/components/audit/audit-ledger-view.tsx`:
  - Master container combining status summary cards, integrity badge with "Verify Chain Integrity" on-demand trigger, and the ledger table.
- Create `src/app/audit/page.tsx`:
  - Server-rendered page wrapped in `AppShell` with pre-fetched initial audit records and chain integrity status.
- Update `src/components/layout/sidebar.tsx`:
  - Add `{ label: "Audit Ledger", href: "/audit", icon: ShieldCheck }` to the primary navigation items.

### Task 4: Unit & Component Tests
- `tests/unit/audit/audit-ledger.test.ts`:
  - Verify deterministic canonical hashing.
  - Verify sequence and prev_hash linking from genesis to multiple blocks.
  - Verify tamper detection when payload is mutated.
  - Verify tamper detection when an intermediate event is deleted or swapped.
  - Verify tamper detection when sequence is altered.
- `tests/unit/api/audit-routes.test.ts`:
  - Test `GET /api/audit` filtering and pagination.
  - Test `POST /api/audit` recording.
  - Test `GET /api/audit/verify` integrity check.
- `tests/unit/components/audit-ledger.test.tsx`:
  - Test rendering of ledger records, integrity badge states, on-demand verification click, and search filter input.

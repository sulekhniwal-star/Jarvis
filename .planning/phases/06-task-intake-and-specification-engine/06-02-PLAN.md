  <action>
    1. Update `src/lib/repositories/types.ts`:
       - Export `Specification`, `SpecificationInsert`, `SpecificationUpdate` based on `Tables<"specifications">`, etc.
    2. Author `src/lib/repositories/specification-repository.ts`:
       - Inherit from `BaseRepository`.
       - Method `create(payload: { taskId: string; scope: string; exclusions: string; acceptanceCriteria: unknown[]; rawUserPrompt: string; version?: number }): Promise<Specification>`:
         Inserts a new specification record with default version = 1.
       - Method `findByTaskId(taskId: string): Promise<Specification | null>`:
         Retrieves latest specification for a task (`order("version", { ascending: false }).limit(1)`).
       - Method `findAllVersions(taskId: string): Promise<Specification[]>`:
         Retrieves all versions ordered by version ascending.
       - Method `createRevision(taskId: string, payload: { scope: string; exclusions: string; acceptanceCriteria: unknown[]; rawUserPrompt: string }): Promise<Specification>`:
         Queries highest existing version for `taskId`, increments by 1, and inserts new revision.
  </action>
</task>

<task type="auto">
  <name>Implement Task Intake and Clarification API route handlers</name>
  <files>
    src/app/api/tasks/intake/route.ts
    src/app/api/tasks/[id]/clarify/route.ts
  </files>
  <action>
    1. Author `src/app/api/tasks/intake/route.ts`:
       - `POST` handler accepting `{ projectId: string; title: string; rawPrompt: string; userId?: string }`.
       - Validates input fields using Zod.
       - Creates task via `TaskRepository.create({ projectId, title, description: rawPrompt, status: "intake" })`.
       - Transitions task status to `specifying` via `TaskStateMachine`.
       - Dispatches `SpecifierAgent.specify({ rawPrompt, projectId, userId })`.
       - If `status === "needs_clarification"`:
         - Returns 200 with `{ taskId, status: "needs_clarification", ambiguity: ..., questions: ... }`.
       - If `status === "specified"`:
         - Persists specification via `SpecificationRepository.create(...)`.
         - Returns 201 with `{ taskId, status: "specified", specification: ... }`.
    2. Author `src/app/api/tasks/[id]/clarify/route.ts`:
       - `POST` handler accepting route param `id` and body `{ answers: ClarificationAnswer[]; userId?: string }`.
       - Fetches task and verifies it exists and is in `specifying` status.
       - Dispatches `SpecifierAgent.specifyWithClarifications(...)`.
       - If `specified`:
         - Persists specification via `SpecificationRepository.create(...)`.
         - Returns 200 with `{ taskId, status: "specified", specification: ... }`.
       - If still `needs_clarification`:
         - Returns 200 with updated questions.
  </action>
</task>

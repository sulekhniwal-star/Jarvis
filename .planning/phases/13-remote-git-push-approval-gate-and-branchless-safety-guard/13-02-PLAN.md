# Plan 13.2: Remote Push Gate Service, Route Handler & Telegram Decision Wiring

## Objective
Implement the human-in-the-loop authorization gate for remote pushes (`PushGateService`), an authenticated Next.js App Router endpoint (`/api/git/push`), and wire real-time execution directly into the `TelegramDecisionService` so owners can authorize and trigger remote pushes directly from Telegram or web UI (`REQ-GH-03`, `NFR-SEC-01`, `REQ-TG-05`).

  <name>Author PushGateService</name>

  <action>
    1. Author `src/lib/git/push-gate.ts`:
       - Define interfaces:
         - `PushApprovalRequest`: `{ testProof?: string; taskId?: string; notes?: string }`
         - `PushExecutionResult`: `{ success: boolean; pushedCommit: string; remoteRef: string; aheadCount: number; output: string; executedAt: string }`
       - Implement `PushGateService`:
         - Dependencies: `ApprovalRepository`, `TelegramApprovalService` (optional), `auditLogger` (or Supabase client).
         - Method `requestPushApproval(userId: string, request?: PushApprovalRequest)`:
           - Call `validatePrePush()` from `push-validator.ts`.
           - If `!validation.isReady`, throw error or return `{ success: false, validation, errors: validation.errors }`.
           - Create approval record in `ApprovalRepository`:
             - `actionType: 'git_remote_push'`
             - `targetResource: 'origin/main'`
             - `scope`: `{ headCommitSha: validation.headCommitSha, headCommitMessage: validation.headCommitMessage, aheadCount: validation.aheadCount, commits: validation.commits, filesChanged: validation.filesChanged, testProof: request?.testProof, notes: request?.notes }`
             - `expiresAt`: Date (now + 1 hour).
             - `taskId`: request?.taskId.
           - If `TelegramApprovalService` is configured, call `sendActionApprovalCard({ approval, task })`.
           - Return `{ success: true, approval, validation }`.
         - Method `executePush(approvalId: string, userId: string)`:
           - Fetch approval from `ApprovalRepository`: must exist and belong to `userId`.
           - Assert `approval.status === 'approved'`. If not, throw `Error("Approval is '${approval.status}'. Push rejected.")`.
           - Assert `approval.action_type === 'git_remote_push'`.
           - Check expiration: if `new Date(approval.expires_at) < new Date()`, throw error.
           - Re-run safety check: `validatePrePush()`. Verify active branch is `main` and working tree is clean.
           - Execute `git push origin main` via `execFileSync('git', ['push', 'origin', 'main'], { ... })`.
           - Log audit record in Supabase `audit_events`.
           - Return `PushExecutionResult`.
    2. Export `PushGateService` from `src/lib/git/index.ts`.
  </action>
</task>

  <action>
    1. Author `src/app/api/git/push/route.ts`:
       - Handle `POST` requests.
       - Authenticate user via Supabase auth server helper or bearer token.
       - Parse request body: `{ action: "request" | "execute", approvalId?: string, testProof?: string, taskId?: string }`.
       - If `action === "request"`: invoke `pushGateService.requestPushApproval(user.id, { testProof, taskId })`. Return HTTP 200/400.
       - If `action === "execute"`: require `approvalId`, invoke `pushGateService.executePush(approvalId, user.id)`. Return HTTP 200/400.
    2. Wire into `src/lib/telegram/decision.ts`:
       - In `processActionDecision` and `handleCliDecision`:
         - If `approval.action_type === "git_remote_push"` and `decision === "approved"`:
           - Automatically invoke `pushGateService.executePush(approval.id, userId)`.
           - On success, format the Telegram receipt or notification with the pushed commit SHA and ahead count!
           - If the push command fails, handle the error gracefully and alert the user in Telegram without crashing the webhook handler.
  </action>
</task>

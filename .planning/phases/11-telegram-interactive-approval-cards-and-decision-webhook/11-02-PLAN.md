# Plan 11.2: Callback Query Decision Processing, In-Place Card Edits & CLI Commands

## Objective
Implement `TelegramDecisionService` to process Telegram `callback_query` events, invoke immediate acknowledgment, atomically update plan and action states in Supabase, edit approval cards in-place with immutable receipts, wire webhook/polling pipelines, and support `/approve` and `/reject` CLI commands (`REQ-TG-05`).

  <action>
    1. Author `src/lib/telegram/decision.ts`:
       - Define interface `DecisionDependencies`:
         - `client?: TelegramClient`
         - `planRepo?: PlanRepository`
         - `approvalRepo?: ApprovalRepository`
         - `taskRepo?: TaskRepository`
       - Class `TelegramDecisionService`:
         - `handleCallbackQuery(callbackQuery: TelegramCallbackQuery, userId: string): Promise<{ success: boolean; message: string }>`:
           1. Immediate acknowledgment: `client.answerCallbackQuery(callbackQuery.id, "Processing decision...")`.
           2. Parse `callbackQuery.data`:
              - Matches prefix `appr:plan:`, `rejc:plan:`, `appr:act:`, `rejc:act:`.
              - Returns error if format unrecognized.
           3. For plan decision (`appr:plan` or `rejc:plan`):
              - Fetch plan by id via `planRepo.getById(planId, userId)`.
              - If plan status is not `pending_approval` (e.g. already `approved` or `rejected`), edit message with updated status receipt and return `{ success: false, message: "Plan already decided." }`.
              - If `appr:plan`:
                - `planRepo.updateStatus(planId, "approved")`
                - Transition associated task to `queued`
                - Edit Telegram message in-place with `formatDecisionReceipt("plan", task.title, "approved", new Date())` and empty `inline_keyboard: []`.
              - If `rejc:plan`:
                - `planRepo.updateStatus(planId, "rejected")`
                - Transition associated task or annotate rejection
                - Edit Telegram message in-place with `formatDecisionReceipt("plan", task.title, "rejected", new Date())` and empty `inline_keyboard: []`.
           4. For action decision (`appr:act` or `rejc:act`):
              - Fetch approval by id via `approvalRepo.getById(approvalId, userId)`.
              - If status !== "pending", edit message with updated status receipt.
              - Call `approvalRepo.recordDecision(approvalId, userId, decision, "Decided via Telegram")`.
              - Edit Telegram message in-place with `formatDecisionReceipt("action", approval.action_type, decision, new Date())` and empty `inline_keyboard: []`.
         - `handleCliDecision(command: "approve" | "reject", targetId: string, userId: string, reason?: string): Promise<string>`:
           - Resolves whether targetId is plan or approval.
           - Executes appropriate state transition.
           - Returns formatted MarkdownV2 string confirmation.
    2. Export `TelegramDecisionService` from `src/lib/telegram/index.ts`.
    3. Author `tests/unit/telegram/decision.test.ts`:
       - Test 1: Callback query for plan approval transitions plan to approved, task to queued, and edits message in-place.
       - Test 2: Callback query for plan rejection transitions plan to rejected and edits message in-place.
       - Test 3: Action approval transitions approval record to approved and edits message in-place.
       - Test 4: Idempotent handling: second click on already approved plan displays already decided notice without duplicate updates.
       - Test 5: Immediate answerCallbackQuery invocation.
  </action>
</task>

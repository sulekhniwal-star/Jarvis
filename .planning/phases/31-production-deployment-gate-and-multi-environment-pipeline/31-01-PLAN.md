# Plan 31.1: Deployment Manager Core, Production Promotion Gate & REST APIs

## Objective
Implement the `DeploymentManager` service, `DeploymentRepository`, production promotion approval gate (`REQ-DEP-01`), preview URL tracking, rollback execution engine (`REQ-DEP-02`), and supporting REST API endpoints.

## Task Breakdown

### Task 1: Deployment Domain Types & Repository
- Create `src/lib/deployment/types.ts`:
  - Define `DeploymentEnvironment` (`"preview" | "production"`).
  - Define `DeploymentStatus` (`"pending_approval" | "building" | "deployed" | "failed" | "rolled_back"`).
  - Define `DeploymentRecord`, `DeploymentFilterOptions`, `PromotionRequestInput`, and `RollbackResult`.
- Create `src/lib/repositories/deployment-repository.ts`:
  - `createDeployment(record)`: Persists deployment record.
  - `getDeployment(id)`: Retrieves record by ID.
  - `listDeployments(filters)`: Retrieves paginated records with optional environment and status filters.
  - `updateDeployment(id, updates)`: Updates status, URLs, and timestamps.
  - `getActiveProductionDeployment()`: Returns the currently deployed production record.

### Task 2: Deployment Manager & Production Promotion Gate (`REQ-DEP-01`, `REQ-DEP-02`)
- Create `src/lib/deployment/deployment-manager.ts`:
  - `createPreviewDeployment(params)`:
    - Generates preview deployment for the current commit SHA.
    - Sets preview URL (e.g. `https://jarvis-preview-<sha>.vercel.app`).
    - Deploys without approval gating (`status: "deployed"`).
  - `requestProductionPromotion(userId, params)`:
    - Verifies target commit is on `main` and passes verification.
    - Creates pending record in `public.approvals` with `action_type = "production_deployment"`.
    - Dispatches Telegram interactive approval card with HMAC-signed buttons.
    - Saves deployment record in `pending_approval` state.
  - `executeProductionPromotion(deploymentId, approvalId, userId)`:
    - Verifies approval record exists and has status `approved`.
    - Throws `UnapprovedProductionDeploymentError` if unapproved or expired.
    - Updates deployment to `deployed` with `production_url = "https://jarvis.app"` and `deployed_at`.
    - Logs hash-chained event to `audit_events` via `AuditLedgerService`.
  - `executeRollback(deploymentId, userId)`:
    - Validates target deployment was previously `deployed` in `production`.
    - Sets current production deployment to `rolled_back` with `rollback_target_id = targetId`.
    - Promotes target deployment commit back to active production pointer.
    - Emits audit log entry.

### Task 3: REST API Routes
- Create `src/app/api/deployments/route.ts`:
  - `GET`: Authenticated endpoint listing deployments with filters (`environment`, `status`, `limit`, `offset`).
  - `POST`: Authenticated endpoint triggering preview deployment.
- Create `src/app/api/deployments/production/request/route.ts`:
  - `POST`: Initiates production deployment approval request.
- Create `src/app/api/deployments/production/promote/route.ts`:
  - `POST`: Executes approved production promotion.
- Create `src/app/api/deployments/[id]/rollback/route.ts`:
  - `POST`: Executes instant rollback to target deployment.

### Task 4: Unit & API Route Tests
- `tests/unit/deployment/deployment-manager.test.ts`:
  - Test preview deployment generation and URL creation.
  - Test production promotion request creating approval.
  - Test production promotion execution blocking on unapproved/rejected approvals.
  - Test successful production promotion with valid approval.
  - Test rollback execution and active production pointer update.
- `tests/unit/api/deployments-routes.test.ts`:
  - Test `GET /api/deployments` list with filters.
  - Test `POST /api/deployments/production/request`.
  - Test `POST /api/deployments/production/promote`.
  - Test `POST /api/deployments/[id]/rollback`.

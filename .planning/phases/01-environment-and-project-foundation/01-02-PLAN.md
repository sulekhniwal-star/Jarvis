# Plan 1.2: Git Safety Guard & Diff Inspection Tooling

## Objective
Implement the automated Git safety guard module, command validator, diff inspector, and standalone CLI runner. This enforces the mandatory `main`-only branch policy (REQ-ENV-02, NFR-SEC-01), blocks creation or checkout of non-`main` branches, prevents force-pushes, and scans commit diffs for accidental credentials (NFR-SEC-02).

<task type="auto">
  <name>Implement Git Safety Guard core module and branch/command unit tests</name>
  <files>
    src/lib/git/types.ts
    src/lib/git/guard.ts
    tests/unit/git/guard.test.ts

  <action>
    Create the core Git governance module to enforce the mandatory `main`-only policy:
    1. Define contracts in `src/lib/git/types.ts`:
       - `BranchValidationResult`: `{ isValid: boolean; currentBranch: string; error?: string }`
       - `WorkingTreeStatus`: `{ isClean: boolean; modified: string[]; untracked: string[]; staged: string[] }`
       - `CommandValidationResult`: `{ isAllowed: boolean; reason?: string; violatedRule?: string }`
       - `GitGuardOptions`: `{ cwd?: string; throwOnError?: boolean }`
       - Error class `GitPolicyViolationError` extending `Error`.
    2. Implement `src/lib/git/guard.ts`:
       - `getCurrentBranch(cwd?: string): string`: runs `git branch --show-current` via `execFileSync` with non-interactive flags (`GIT_TERMINAL_PROMPT: '0'`).
       - `verifyActiveBranchIsMain(cwd?: string, options?: GitGuardOptions): BranchValidationResult`: checks if current branch is strictly `'main'`. If not, returns invalid and optionally throws `GitPolicyViolationError`.
       - `getWorkingTreeStatus(cwd?: string): WorkingTreeStatus`: runs `git status --porcelain` and parses output into modified, untracked, and staged file lists.
       - `validateGitCommand(command: string | string[]): CommandValidationResult`: inspects git CLI arguments before execution.
         Disallows:
         - Creating/switching branches: `checkout -b`, `switch -c`, `branch <name>`, `checkout <other-branch>`, `switch <other-branch>` (unless target is strictly `main`).
         - Force pushes: `push --force`, `push -f`, `push --force-with-lease`.
         - Destructive history rewrites: `reset --hard origin/main`, `rebase -i`.
         Returns `{ isAllowed: false, reason, violatedRule }` on any violation.
    3. Implement unit tests in `tests/unit/git/guard.test.ts`:
       - Test `verifyActiveBranchIsMain`: accepts `'main'`, rejects `'feature/abc'`, `'dev'`, `'chore-123'`, `'master'`, and detached HEADs.
       - Test `validateGitCommand`:
         - Permits safe commands (`git status`, `git add .`, `git commit -m "feat: init"`, `git diff`, `git log`, `git checkout main`).
         - Rejects `git checkout -b new-branch`.
         - Rejects `git switch -c new-feature`.
         - Rejects `git branch temp`.
         - Rejects `git push --force`.
         - Rejects `git push -f origin main`.
         - Rejects `git push --force-with-lease`.
       - Test `getWorkingTreeStatus`: correctly parses empty output (clean) and multi-line porcelain output (dirty).

    AVOID: Using shell string concatenation (`exec(cmd)`) which is vulnerable to command injection.
    USE: `execFileSync('git', args)` with separate argument arrays.
  </action>
  <verify>
    npx vitest run tests/unit/git/guard.test.ts
  </verify>
  <done>
    All Git guard unit tests pass with 100% assertions satisfied.
  </done>
</task>

<task type="auto">
  <name>Implement diff inspection utility, secret scanning, and CLI runner script</name>
  <files>
    src/lib/git/diff.ts
    scripts/git-guard.ts
    tests/unit/git/diff.test.ts
  </files>
  <action>
    Implement diff analysis and CLI enforcement tooling:
    1. Implement `src/lib/git/diff.ts`:
       - `inspectCommitDiff(options?: { cached?: boolean; ref?: string; cwd?: string })`: runs `git diff` or `git diff --cached` or `git diff <ref>`.
       - Parses diff into `filesChanged: string[]`, `totalAdditions: number`, `totalDeletions: number`.
       - Scans added diff lines (`+...`) for secret patterns (satisfying NFR-SEC-02):
         - Private keys: `-----BEGIN (RSA |EC |DSA |OPENSSH )?PRIVATE KEY-----`
         - API keys and tokens: `sk-[a-zA-Z0-9_-]{20,}`, `ghp_[a-zA-Z0-9]{36}`, `xoxb-[a-zA-Z0-9-]+`
         - High-entropy JWT tokens: `eyJ[a-zA-Z0-9_-]+\.eyJ[a-zA-Z0-9_-]+\.[a-zA-Z0-9_-]+`
         - Explicit secret assignments in `.env` variables (`SUPABASE_SERVICE_ROLE_KEY=...`, `OPENROUTER_API_KEY=...`)
       - Returns `DiffInspectionResult`: `{ hasSecrets: boolean; detectedPatterns: string[]; filesChanged: string[]; totalAdditions: number; totalDeletions: number; rawDiff: string }`.
    2. Implement `scripts/git-guard.ts`:
       - CLI script accepting subcommands:
         - `check-branch`: asserts current branch is `main`. Exits with code 1 and error message if not.
         - `check-clean`: asserts working tree is clean. Exits with code 1 if uncommitted changes exist.
         - `scan-diff`: runs `inspectCommitDiff({ cached: true })` and fails if secrets are detected.
         - `pre-commit`: runs `check-branch` and `scan-diff` in sequence.
       - Prints clear status output (e.g. `[Git Guard] ✓ Active branch is main`).
    3. Implement unit tests in `tests/unit/git/diff.test.ts`:
       - Tests diff parser with mock diff strings (files changed, additions, deletions).
       - Tests secret pattern detection with mock diff additions containing simulated keys vs clean code.
       - Tests CLI subcommands logic.

    AVOID: False positives on placeholder examples like `sk-xxx` in documentation or tests.
    USE: Regexes requiring realistic key formats while catching real private keys and API tokens.
  </action>
  <verify>
    npx vitest run tests/unit/git/diff.test.ts
    npx tsx scripts/git-guard.ts check-branch
  </verify>
  <done>
    Diff inspection tests pass green, and `scripts/git-guard.ts check-branch` executes against the current repository and verifies branch is `main`.
  </done>
</task>

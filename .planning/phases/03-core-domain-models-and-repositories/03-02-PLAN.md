  <name>Implement deterministic Domain State Machines (Task, Approval, Run) and unit tests</name>
  <files>
    src/lib/state-machines/types.ts

    tests/unit/state-machines/approval-state-machine.test.ts
    tests/unit/state-machines/run-state-machine.test.ts
  </files>
  <action>
    1. Define state machine contracts in `src/lib/state-machines/types.ts`:
       - `InvalidStateTransitionError` extending `Error`.
       - Transition events and state definitions for Task, Approval, and Agent Run.
    2. Implement `src/lib/state-machines/task-state-machine.ts`:
       - `canTransition(current: TaskStatus, target: TaskStatus): boolean`
       - `assertTransition(current: TaskStatus, target: TaskStatus): void`
       - Rules:
         - `intake` -> `specifying` or `cancelled`
         - `specifying` -> `planned` or `cancelled`
         - `planned` -> `awaiting_approval` (if approvals needed) or `running` or `cancelled`
         - `awaiting_approval` -> `running` (if approved) or `cancelled` (if rejected)
         - `running` -> `verifying` or `failed` or `cancelled`
         - `verifying` -> `completed` or `failed`
         - Terminal states (`completed`, `cancelled`) cannot transition further.
    3. Implement `src/lib/state-machines/approval-state-machine.ts`:
       - `canDecide(status: ApprovalStatus, expiresAt: string | Date): boolean`
       - Rules:
         - Only `pending` requests can transition to `approved` or `rejected`.
         - If `new Date() > new Date(expiresAt)`, request is `expired` and cannot be approved.
         - Once `approved`, `rejected`, or `expired`, state is immutable.
    4. Implement `src/lib/state-machines/run-state-machine.ts`:
       - `canTransition(current: AgentRunStatus, target: AgentRunStatus): boolean`
       - Rules:
         - `queued` -> `running`
         - `running` -> `verifying` or `failed` or `timed_out`
         - `verifying` -> `completed` or `failed`
         - `failed` can transition back to `queued` if `retryCount < maxRetries` (bounded retries).
    5. Author unit tests:
       - `tests/unit/state-machines/task-state-machine.test.ts`: Tests every valid transition path and verifies rejection of illegal jumps.
       - `tests/unit/state-machines/approval-state-machine.test.ts`: Tests approval, rejection, expiration timeouts, and immutability.
       - `tests/unit/state-machines/run-state-machine.test.ts`: Tests agent run lifecycle and retry bounds.

    AVOID: Unchecked string mutations that bypass lifecycle validation.
    USE: Pure functions and strongly-typed transition maps.
  </action>
  <verify>
    pnpm test tests/unit/state-machines/
  </verify>
  <done>
    All three state machines implemented and unit tests pass with 100% green output.
  </done>
</task>

       - `completeRun(runId, exitCode, diffPatch, gitCommitHash, testResults)`: Transitions to `completed`.
       - `failRun(runId, errorSummary, exitCode)`: Transitions to `failed`.
       - `addArtifact(runId, data)`: Inserts artifact record (`test_log`, `diff`, `screenshot`, etc.) into `run_artifacts`.

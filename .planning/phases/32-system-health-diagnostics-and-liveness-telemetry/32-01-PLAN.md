# Plan 32.1: System Health Diagnostic Engine & Liveness REST Endpoints

## Objective
Implement the `SystemHealthDiagnosticService` in `src/lib/ops/health-checker.ts`, enforcing sub-200ms non-blocking diagnostic probes across database latency, AI gateway circuit breakers, task queue depth, and Node.js process telemetry (`REQ-OPS-02`, `NFR-REL-03`), accompanied by public liveness and detailed authenticated diagnostic REST endpoints.

## Task Breakdown

### Task 1: Diagnostic Service & Types
- Create `src/lib/ops/health-checker.ts`:
  - Define `HealthCheckStatus` (`"healthy" | "degraded" | "unhealthy"`).
  - Define `SystemHealthReport` containing:
    - `status`: overall health status
    - `timestamp`: ISO timestamp
    - `uptimeSeconds`: process uptime
    - `durationMs`: probe wall-clock time
    - `services`:
      - `database`: status, roundtrip latency ms, error if any
      - `aiGateway`: status, circuit breaker state, provider
      - `taskQueue`: status, active runs count, queued tasks count
      - `system`: status, heap memory (used/total), rss, active child processes
  - Implement `SystemHealthDiagnosticService`:
    - `checkDatabase(timeoutMs)`: ping Supabase with lightweight query, measure round-trip latency, enforce timeout.
    - `checkAIGateway(timeoutMs)`: inspect circuit breaker state and adapter configuration.
    - `checkTaskQueue()`: query queued/running `agent_runs` and active tasks.
    - `checkSystemResources()`: query Node.js memory metrics and `ProcessCancellationRegistry.getActiveCount()`.
    - `getHealthReport(options)`: orchestrate all checks in parallel with an overarching 180ms timeout to guarantee `< 200ms` total execution (`NFR-REL-03`).

### Task 2: REST API Routes
- Create `src/app/api/health/route.ts`:
  - Public liveness & readiness endpoint.
  - Calls `SystemHealthDiagnosticService.getHealthReport()`.
  - Returns HTTP 200 for `healthy` or `degraded`, HTTP 503 for `unhealthy`.
  - Injects headers: `Cache-Control: no-store, no-cache, must-revalidate, max-age=0`.
- Create `src/app/api/health/diagnostics/route.ts`:
  - Authenticated diagnostic endpoint returning full deep breakdown of system state, memory allocation, and connection metrics.
  - Requires valid user session.

### Task 3: Unit & API Route Tests
- Create `tests/unit/ops/health-checker.test.ts`:
  - Test healthy report when all subsystems respond promptly.
  - Test degraded status when database latency exceeds 150ms or circuit breaker is half-open.
  - Test unhealthy status when database connection fails or times out.
  - Test sub-200ms timeout enforcement under simulated slow downstream responses.
- Create `tests/unit/api/health-routes.test.ts`:
  - Test `GET /api/health` returning 200 for healthy/degraded and 503 for unhealthy.
  - Test `GET /api/health` response headers (`no-store`).
  - Test `GET /api/health/diagnostics` enforcing authentication.

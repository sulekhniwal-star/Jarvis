# Plan 32.2: Web UI System Health Widget & Telegram /health Command

## Objective
Construct the real-time `SystemHealthCard` widget in the Web UI dashboard overview, integrate the `/health` Telegram slash command reporting live operational telemetry in MarkdownV2, and verify end-to-end diagnostic observability (`REQ-OPS-02`, `NFR-REL-03`).

## Task Breakdown

### Task 1: Web UI Health Telemetry Card & Dashboard Integration
- Create `src/components/ops/system-health-card.tsx`:
  - Overall status badge (`Healthy`, `Degraded`, `Critical`) with green/amber/red pulsing dots.
  - 4 telemetry tiles:
    - **Database Latency**: Roundtrip time in ms, status indicator, connection state.
    - **AI Inference Gateway**: Provider name, circuit breaker status (`CLOSED`, `HALF_OPEN`, `OPEN`).
    - **Task Execution Queue**: Active running tasks, queued runs count.
    - **System Resources**: Heap memory used vs total (MB), process uptime.
  - Quick "Run Diagnostics" button with live polling and refresh state.
- Update `src/components/dashboard/dashboard-overview.tsx`:
  - Mount `SystemHealthCard` into the dashboard grid layout for prominent operational visibility.

### Task 2: Telegram Bot `/health` Command
- Update `src/lib/telegram/commands.ts`:
  - Add `/health` command handler in `handleTelegramCommand`.
  - Format metrics into MarkdownV2:
    - Overall status header (🟢 / 🟡 / 🔴)
    - Database latency in ms
    - AI Gateway provider & circuit breaker state
    - Task queue running / queued count
    - Memory heap allocation & system uptime
  - Update `/start` command menu with `• /health — Real-time system diagnostics & latency`.

### Task 3: Unit & Component Tests
- Create `tests/unit/components/system-health-card.test.tsx`:
  - Test rendering of healthy, degraded, and unhealthy states.
  - Test service tiles displaying latency, provider, memory, and uptime.
  - Test refresh button click and API fetch trigger.
- Create `tests/unit/telegram/health-command.test.ts`:
  - Test `/start` includes `/health` command.
  - Test `/health` output containing expected MarkdownV2 fields.
  - Test error handling when diagnostic service encounters unexpected failures.

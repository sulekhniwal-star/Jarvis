# Plan 34.1: Proactive Diagnostic Reasoning Engine, Remediation Executor & REST APIs

## Objective
Implement the autonomous diagnostic advisory engine (`REQ-OPS-04`) and 1-click remediation executor (`REQ-OPS-05`), providing heuristic pattern detection across costs, model health, test regressions, stale work items, and hygiene invariants, backed by authenticated REST endpoints.

## Task Breakdown

### Task 1: Advisory Domain Types & Pattern Analyzers
- Create `src/lib/advisory/types.ts`:
  - `RecommendationCategory`: `"cost_budget" | "model_health" | "test_reliability" | "stale_tasks" | "storage_hygiene" | "branch_safety"`
  - `RecommendationSeverity`: `"critical" | "warning" | "info"`
  - `RemediationActionType`: `"unlock_emergency_reserve" | "reset_circuit_breaker" | "prune_storage" | "clean_extraneous_branches" | "expire_stale_approvals" | "retry_failed_task"`
  - `RemediationAction`: type, label, endpoint, payload, description
  - `MaintenanceRecommendation`: id, category, severity, title, description, rationale, detectedAt, remediation
  - `AdvisoryReport`: timestamp, totalRecommendations, criticalCount, warningCount, infoCount, recommendations
- Create `src/lib/advisory/recommendation-engine.ts`:
  - `ProactiveAdvisoryEngine`:
    - Evaluates `detectCostAnomalies(userId)`: 80% daily budget warning, tripped circuit breakers, emergency reserve state.
    - Evaluates `detectModelDegradation()`: checks latency spikes and AI Gateway breaker health.
    - Evaluates `detectTestRegressions()`: checks consecutive agent run test failures.
    - Evaluates `detectStaleWorkItems(userId)`: checks pending approvals nearing expiry (<2h) and abandoned tasks.
    - Evaluates `detectHygieneIssues(cwd)`: checks branch hygiene (`NFR-SEC-04`) and unpruned storage.
    - `generateAdvisoryReport(userId)`: combines all detectors into a prioritized advisory report sorted by severity (`critical` -> `warning` -> `info`).

### Task 2: 1-Click Remediation Executor & Audit Ledger
- Create `src/lib/advisory/remediation-executor.ts`:
  - `RemediationExecutor`:
    - `executeAction(actionType, params, userId)`:
      - `prune_storage`: calls `StoragePruningService.runFullMaintenance({ retentionDays: 30, dryRun: false })`.
      - `clean_extraneous_branches`: calls `cleanExtraneousBranches()`.
      - `unlock_emergency_reserve`: calls `CostRepository.authorizeEmergencyReserve()`.
      - `reset_circuit_breaker`: calls `CostRepository.resetCircuitBreakers()`.
      - `expire_stale_approvals`: calls `StoragePruningService.expireStaleApprovals()`.
    - Emits tamper-evident audit ledger record (`AuditLedgerService.recordEvent({ eventType: "system.remediation_executed", ... })`).

### Task 3: REST API Endpoints
- Create `src/app/api/advisory/route.ts`:
  - `GET`: Authenticated endpoint returning the current `AdvisoryReport`.
- Create `src/app/api/advisory/remediate/route.ts`:
  - `POST`: Authenticated endpoint accepting `{ actionType: string, params?: Record<string, unknown> }`, executing the remediation via `RemediationExecutor`, and returning the outcome report.

### Task 4: Unit & API Route Tests
- Create `tests/unit/advisory/recommendation-engine.test.ts`:
  - Test detection of budget exhaustion and tripped circuit breakers.
  - Test detection of model degradation.
  - Test detection of repeated test regressions.
  - Test detection of stale approvals and branch safety violations.
  - Test priority ordering in advisory report.
- Create `tests/unit/advisory/remediation-executor.test.ts`:
  - Test execution of each supported remediation action.
  - Test audit ledger logging upon remediation completion.
  - Test error handling when action fails.
- Create `tests/unit/api/advisory-routes.test.ts`:
  - Test authentication requirement on `GET /api/advisory` and `POST /api/advisory/remediate`.
  - Test `GET` returning valid advisory structure.
  - Test `POST` validating action types and executing remediation.
